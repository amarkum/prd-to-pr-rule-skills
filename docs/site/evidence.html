Stage 4: Test

Evidence that holds

A green check mark is a claim. In public benchmarks, 15.7% to 28.4% of "passing" patches were wrong because the tests were weak. The standard turns a test run into proof a reviewer can trust without re-running anything: computed by scripts, tied to a commit, re-run in CI and attested.

What evidence.py run checks, in order

PASS is the only verdict that opens a pull request. A failure gives FAIL; a gap (an unlisted file, a dirty tree) gives INCOMPLETE.

    Three levels of trust

    LEVEL 1 · LOCAL

    The session proves its own work

    The verify skill runs evidence.py on the developer's machine or the agent's sandbox, at a committed SHA on a clean tree. The PR hooks read this result.

    LEVEL 2 · CI RE-RUN

    A clean runner repeats it

    The shared workflow's evidence job checks out the PR's head commit, re-runs the same script, adds changed-line coverage and posts the verdict. It's the required check ai-sdlc / evidence.

    LEVEL 3 · ATTESTED

    The artifact can't be swapped

    The evidence bundle is uploaded and attested with Sigstore, tied to the commit. Reviewers trust this, not the PR description.
