What goes where

Two questions place almost any piece of guidance: must it hold every time, and who needs it, when? Skills and rules make the right thing likely. Hooks, scripts, CI checks and policy make the wrong thing impossible, or at least visible.

Four layers, from the organisation down to one developer

Higher layers win. A developer can't switch off what policy enforces, and a repo can't widen what the standard denies.

How it reaches everyone, with nothing to install or copy

An administrator sets up three channels once. After that, merging to the standard's main branch is the release: there's no version to bump and no PR in any product repo, and a revert rolls it back the same way.

A change, from merge to everyone

  1. A PR to the standard: CODEOWNERS review it, and the validate checks (tests, strict plugin validation, actionlint) must pass.
  2. Merge to main. That is the release: plugins carry no version, so Claude Code versions them by commit.
  3. Developers get it from auto-update and use it from their next launch, or straight away with /reload-plugins.
  4. CI uses it on the next run in any repo. Slack and claude.ai get it when the sync runs on the push.
  5. To roll back, revert the commit. To hold everyone on a known-good commit, pin ref in managed settings.

Setup steps: policy/README.md. Without managed settings, aisdlc.py init --repo-plugins or vendor are the fallbacks.

Which surfaces load what

Claude Code runs in more places than a terminal, and not every place loads the same things. Managed settings put the plugins on developer machines and in web sessions; the shared workflow installs them in CI; Claude in Slack gets them from its own admin settings and doesn't run repo hooks. That's why the CI required checks are the gate that holds everywhere.

What it costs to have the standard installed

Skill and subagent descriptions sit in every session's context; their bodies load only when used. Hooks, scripts and policy cost nothing in context. The standard's budget is about 2,000 tokens for sdlc-core.
